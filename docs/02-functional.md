# Функциональные требования

## Страница транзакций

### Назначение

Страница предназначена для добавления, просмотра, редактирования и удаления доходов и расходов. Пользователь может просматривать историю операций, находить нужные транзакции и анализировать их с помощью группировок и фильтрации.

### Отображение списка

Транзакции отображаются в виде списка, сгруппированного по дням. Пользователь может переключить группировку на месяцы.

Пользователь может выбрать произвольный период просмотра. Период и группировка определяются по фактической дате операции.

Группы и транзакции внутри групп сортируются по фактической дате в порядке убывания: сначала более поздние даты.

Для каждой группы отображается общий итог по входящим в неё транзакциям.

Транзакции загружаются постепенно по мере прокрутки списка (infinite scroll); весь список не загружается сразу.

### Группы списка

Группы можно сворачивать и раскрывать по отдельности. Общая кнопка позволяет раскрыть или свернуть все группы, отображаемые в данный момент.

### Поиск

Строка поиска позволяет находить транзакции по категории и описанию.

### Тип операции и категория

Тип операции определяется выбранной категорией. Категории доходов и расходов разделены по типу операции.

### Создание транзакции

Форма создания транзакции содержит:

- Категорию.
- Сумму.
- Дату операции.
- Учётный период.
- Описание — необязательное поле.
- Возможность переопределить регулярность, заданную для категории.

#### Дата операции

По умолчанию в поле даты операции указывается текущая дата.

Если пользователь создаёт транзакцию с другой датой, дата этой транзакции подставляется в поле даты следующей создаваемой транзакции в рамках текущего сеанса. Это поведение действует независимо от страницы, с которой пользователь открыл форму создания транзакции.

Дата, сохранённая в рамках сеанса, не сохраняется после обновления страницы или открытия новой сессии.

#### Учётный период

Учётный период по умолчанию соответствует месяцу даты операции. Пользователь может вручную переопределить учётный период.

Пока период не переопределён вручную, при изменении даты операции учётный период автоматически следует за её месяцем. После ручного переопределения изменение даты операции не меняет выбранный учётный период.

#### Регулярность

По умолчанию для транзакции используется значение регулярности, заданное для её категории. Пользователь может переопределить это значение для конкретной транзакции.

Если пользователь переопределил регулярность, а затем сменил категорию, переопределение сбрасывается и применяется значение регулярности по умолчанию для новой категории.

### Карточка транзакции

В карточке транзакции отображаются:

- Категория.
- Сумма.
- Дата операции.
- Регулярность, визуально выделенная в карточке.
- Учётный период, если он отличается от месяца даты операции.

Из карточки пользователь может открыть форму редактирования транзакции в модальном окне или инициировать её удаление.

### Редактирование и удаление

Редактирование транзакции открывает модальное окно с формой транзакции.

Перед удалением транзакции пользователь должен подтвердить действие.

## Страница категорий

### Назначение

Страница предназначена для управления категориями и подкатегориями доходов и расходов.

### Отображение категорий

Категории отображаются в виде карточек. В карточке отображаются название, регулярность, цвет и эмодзи категории.

Подкатегории отображаются внутри карточки родительской категории. Поддерживается только один уровень вложенности: родительская категория и её подкатегории. Дерево подкатегорий запрещено.

Категории разделены на два вертикально расположенных раздела: сначала расходы, затем доходы. Разделы не сворачиваются.

Для каждой карточки доступны действия редактирования и удаления.

### Создание и редактирование категории

Форма категории содержит:

- Название.
- Тип: доход или расход.
- Флаг регулярности.
- Родительскую категорию — необязательное поле.
- Эмодзи.
- Цвет.

Эмодзи выбирается с помощью встроенного селектора. Цвет выбирается из готовой палитры. Эмодзи и цвет обязательны.

### Родительские категории и подкатегории

Тип подкатегории должен совпадать с типом родительской категории. Родителем может быть только категория верхнего уровня; назначать подкатегорию родителем нельзя.

Регулярность родительской категории и её подкатегорий задаётся независимо.

Родительскую категорию можно выбрать при создании транзакции.

### Ограничения на удаление и изменение типа

Категорию, используемую хотя бы в одной транзакции, нельзя удалить или изменить её тип. Тип родительской категории нельзя изменить, если в транзакциях используется она сама или хотя бы одна из её подкатегорий.

Родительскую категорию можно удалить только после удаления всех её подкатегорий.

При изменении типа родительской категории тип всех её подкатегорий изменяется вместе с ней.

## Страница статистики

### Общие параметры анализа

На странице доступны общие параметры, влияющие на отображаемую статистику:

- Режим учёта: по фактическим датам операций или по учётным периодам.
- Период анализа. По умолчанию выбран весь период.
- Временной разрез: по дням, месяцам или годам. Для режима учёта по учётным периодам разрез по дням недоступен.
- Тип операций: все операции, только регулярные или только нерегулярные.

По умолчанию используется режим учёта по фактическим датам и разрез по месяцам. Выбранный пользователем режим учёта сохраняется и применяется при последующих посещениях страницы.

### Общие итоги и динамика

В верхней части страницы отображаются общий график финансового результата по выбранному временному разрезу и общие итоги за выбранный период:

- Общий финансовый результат — доходы минус расходы.
- Общий доход.
- Общий расход.

Отрицательный финансовый результат отображается красным цветом, положительный — зелёным. Это правило применяется к значению результата на графике и к общему финансовому результату.

### Анализ расходов и доходов

Под общими итогами последовательно расположены сначала блок расходов, затем блок доходов. Блоки не сворачиваются.

Каждый блок содержит:

1. График динамики расходов или доходов в выбранном периоде и временном разрезе.
2. График динамики по категориям: для каждой категории отображается отдельная линия, использующая цвет этой категории.
3. Кольцевую диаграмму распределения расходов или доходов по категориям за выбранный период без временного разреза.

В графике динамики по категориям по умолчанию выбраны все категории соответствующего типа. Пользователь может выбрать отдельные категории, выбрать все категории или сбросить выбор. Выбор категорий влияет только на этот график.

Итог родительской категории включает операции, отнесённые непосредственно к ней, и итоги её подкатегорий.

Кольцевая диаграмма показывает данные за выбранный период: при выборе всего периода — за всё время, при выборе месяца — за этот месяц. При нажатии на сегмент родительской категории диаграмма показывает распределение по её подкатегориям.

## Публичная стартовая страница (`/`)

Страница доступна по корневому адресу сайта `/` и предназначена для входа в приложение.

Страница занимает весь экран и не имеет прокрутки. На ней отображаются:

- Название проекта.
- Краткое описание или девиз — текст будет определён позже.
- Абстрактная графика.
- Кнопка входа через Яндекс ID.

Если авторизованный пользователь открывает страницу `/`, он перенаправляется на дашборд рабочего пространства.

После успешного входа через Яндекс ID пользователь попадает на дашборд рабочего пространства. Попытка открыть страницу рабочего пространства без авторизации перенаправляет пользователя на `/`.

## Дашборд рабочего пространства

### Назначение

Дашборд рабочего пространства показывает краткие итоги текущего календарного месяца и помогает сравнить текущие результаты с предыдущим месяцем.

### Основной показатель и сравнение периодов

Основной финансовый показатель — финансовый результат (доходы минус расходы) с первого числа текущего календарного месяца по текущую дату. Для сравнения показывается результат за такой же отрезок предыдущего месяца и итог предыдущего месяца за весь месяц.

Для показателя темпа трат также показывается значение за сопоставимый отрезок предыдущего месяца и итог предыдущего месяца за весь месяц.

Сравнение учитывает календарные месяцы, а не скользящие 30 дней. Если в предыдущем месяце меньше дней, сравниваемый отрезок заканчивается последним днём этого месяца.

Режим учёта на дашборде соответствует выбранному пользователем режиму учёта и сохраняется вместе с ним.

### Динамика по дням

На дашборде отображается дневной график сравнения текущего и предыдущего месяцев.

В режиме учёта по фактическим датам транзакции располагаются на графике по фактическим датам операций.

В режиме учёта по учётным периодам транзакция располагается в учётном месяце на дне, номер которого соответствует дню её фактической даты. Если такого дня в учётном месяце нет, транзакция располагается на последний день этого месяца.

### Темп трат

На дашборде предусматривается показатель темпа трат за текущий месяц с сопоставлением с предыдущим месяцем. Для предыдущего месяца также показывается значение за полный месяц.

Способ расчёта темпа трат и состав связанных с ним показателей пока не определены.

### Изменения по категориям

На дашборде отображаются три наиболее заметных изменения в категориях доходов и расходов в целом. Значимость изменения определяется по проценту изменения относительно сопоставимого периода предыдущего месяца, без минимального порога.

Для каждого изменения показываются числовые значения и текстовое пояснение. Рост расходов и снижение доходов обозначаются красным цветом; снижение расходов и рост доходов — зелёным. Правило отображения процентного изменения, если значение за предыдущий период равно нулю, пока не определено.

## Общие сценарии рабочего пространства

### Меню пользователя и выход

В интерфейсе рабочего пространства отображается пользовательское меню с выпадающим списком. В меню доступно действие выхода из аккаунта.

После выхода пользователь перенаправляется на публичную стартовую страницу `/`.

### Навигация

Из рабочего пространства доступны страницы дашборда, транзакций, статистики и категорий. Визуальное расположение навигации определяется в спецификации дизайна.

### Отсутствие транзакций

Если транзакций ещё нет, на дашборде и странице статистики вместо содержимого страницы отображается заглушка с сообщением об отсутствии транзакций и кнопкой создания транзакции.
