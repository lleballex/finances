# Модель данных

Документ предназначен для описания сущностей данных, их атрибутов, типов, связей и ограничений.

## Пользователь

Таблица: `"user"`.

`user` — зарезервированное слово PostgreSQL, поэтому имя таблицы заключается в двойные кавычки.

| Колонка | Тип | Ограничения |
|---|---|---|
| `id` — Идентификатор пользователя | `uuid` | Первичный ключ, `NOT NULL` |
| `created_at` — Дата создания | `timestamptz` | `NOT NULL`, по умолчанию `now()` |
| `updated_at` — Дата изменения | `timestamptz` | `NOT NULL`, по умолчанию `now()`; обновляется при изменении записи |
| `email` — Электронная почта | `text` | `NULL` |
| `first_name` — Имя | `text` | `NULL` |
| `last_name` — Фамилия | `text` | `NULL` |
| `avatar_url` — URL аватара | `text` | `NULL` |
| `yandex_id` — Идентификатор пользователя в Яндексе | `text` | `NOT NULL`, уникальное значение |

Уникальное ограничение на `yandex_id` создаёт соответствующий уникальный индекс. Отдельный индекс для `id` создаётся первичным ключом.

Режим учёта хранится в клиентском сторе и в таблице пользователя не сохраняется.

## Категория

Таблица: `category`.

| Колонка | Тип | Ограничения |
|---|---|---|
| `id` — Идентификатор категории | `uuid` | Первичный ключ, `NOT NULL` |
| `created_at` — Дата создания | `timestamptz` | `NOT NULL`, по умолчанию `now()` |
| `updated_at` — Дата изменения | `timestamptz` | `NOT NULL`, по умолчанию `now()`; обновляется при изменении записи |
| `user_id` — Идентификатор пользователя | `uuid` | `NOT NULL`, внешний ключ → `"user".id` |
| `name` — Название | `text` | `NOT NULL` |
| `type` — Тип операции | `text` | `NOT NULL`, допустимые значения: `income`, `expense` |
| `is_regular` — Регулярность по умолчанию | `boolean` | `NOT NULL`, `DEFAULT false` |
| `parent_id` — Идентификатор родительской категории | `uuid` | `NULL`, внешний ключ → `category.id` |
| `emoji` — Эмодзи | `text` | `NOT NULL` |
| `color` — Цвет | `text` | `NOT NULL` |

Первичный ключ создаёт индекс на `id`. Предусматриваются индексы на `user_id` и `parent_id` для выборки категорий пользователя и подкатегорий.

У каждого пользователя может быть много категорий. Категория может иметь много подкатегорий; у подкатегории может быть не более одной родительской категории. Поддерживается только один уровень вложенности. Тип подкатегории должен совпадать с типом родителя, родителем может быть только категория верхнего уровня. Регулярность категории и подкатегорий задаётся независимо.

Название категории не является уникальным. Категорию, используемую транзакциями, нельзя удалить. Родительскую категорию можно удалить только после удаления всех её подкатегорий.

## Транзакция

Таблица: `transaction`.

| Колонка | Тип | Ограничения |
|---|---|---|
| `id` — Идентификатор транзакции | `uuid` | Первичный ключ, `NOT NULL` |
| `created_at` — Дата создания | `timestamptz` | `NOT NULL`, по умолчанию `now()` |
| `updated_at` — Дата изменения | `timestamptz` | `NOT NULL`, по умолчанию `now()`; обновляется при изменении записи |
| `category_id` — Идентификатор категории | `uuid` | `NOT NULL`, внешний ключ → `category.id` |
| `amount` — Сумма | `numeric(12, 2)` | `NOT NULL`, не равна нулю |
| `operation_date` — Дата операции | `date` | `NOT NULL` |
| `accounting_period` — Учётный период | `date` | `NOT NULL`, хранится как первое число месяца |
| `description` — Описание | `text` | `NULL` |
| `is_regular` — Регулярность транзакции | `boolean` | `NOT NULL` |

Сумма хранится со знаком: доход — положительным числом, расход — отрицательным. Форма принимает положительную сумму; знак устанавливается при сохранении по типу выбранной категории. Нулевые значения запрещены.

Учётный период по умолчанию устанавливается в месяц даты операции. Если пользователь вручную меняет период, сохраняется выбранный месяц. Дата операции передаётся как календарная дата без времени.

Регулярность транзакции хранится отдельно от регулярности категории. При создании её значение по умолчанию берётся из категории, пользователь может переопределить его.

Владелец транзакции определяется через её категорию: каждая категория принадлежит пользователю. У каждой транзакции одна категория; категория может использоваться во многих транзакциях. Удаление категории, используемой хотя бы одной транзакцией, запрещено.

Первичный ключ создаёт индекс на `id`. Предусматриваются индексы на `category_id`, `operation_date` и `accounting_period` для связей, списка транзакций и статистики.
